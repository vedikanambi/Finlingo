\section*{Notes}

\begin{itemize}
\item \textbf{Flesch-Kincaid grade:} the earlier baseline (6.13) was measured on a small,
  hand-picked set of 20 examples. The current result (9.89) is measured on the full
  91-example benchmark under stricter quality checks, so the two numbers aren't directly
  comparable -- the current one is the more reliable estimate.
\item \textbf{Faithfulness (retrieved chunk):} this is the metric exactly as specified in the
  proposal. It scores low because the verifier only checks the top 5 retrieved chunks per
  sentence, and the correct chunk is only in that top 5 about 7\% of the time on this
  benchmark. Testing the same retrieval and reranking models on a different benchmark
  (FinanceBench) gives roughly 70\% recall in the same setup, which shows the retrieval code
  itself works -- the current benchmark's document collection just doesn't match its own
  clauses well.
\item \textbf{Risk classification macro-F1:} the 0.75 target assumes strong performance from a
  prompted-only model (no fine-tuning), which is what the proposal specifies for this
  component. This is a known tension in the current design.
\item \textbf{Verifier accuracy on FaithBench:} the fine-tuned verifier improves over its own
  base model by 0.038 balanced accuracy (95\% confidence interval 0.006--0.072, p = 0.02).
  Both the base model and an earlier checkpoint had previously scored at chance level on this
  benchmark, so this is a genuine, statistically solid improvement.
\item \textbf{Comparator rows} (FinBERT, RAGAS-style, SelfCheckGPT-style) are alternative
  methods tested against the same data, not required by the proposal -- included to show how
  the deployed approach compares.
\end{itemize}
